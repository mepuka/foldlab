# packages/moves — agent contract

The TypeScript kernel of the E2 move calculus. Read root `AGENTS.md`
first; scoped laws:

- `src/kernel.ts` is a transliteration of `verify/moves/Moves/Model.lean`,
  one named function per named def. A behavioral difference from the
  model is a bug here by definition, whatever the local code intends.
  Change the kernel only when the model changed first, and land the
  regenerated corpus in the same commit.
- `fixtures/moves-conformance.ndjson` is generated by executing the
  model: `cd verify/moves && lake exe oracle emit 2000 > <fixture>`.
  Its provenance is its first line. Never edit it by hand — the model
  gate (`verify/moves/run.sh`) regenerates and byte-compares it, so a
  hand edit or a stale corpus fails the gate. Changing the emitter, the
  generator seed logic, the codec, or the candidate comparator rewrites
  the corpus and is a wire-format change; say so when you do it.
- The conformance test drives every vector with zero skips and a pinned
  count. A vector that cannot be decoded or replayed is a failure, not
  an omission.
- The mutation tests are the wall's negative controls: each planted
  mutant drops exactly one proved law and must die against the corpus.
  A kernel change that lets a mutant survive has widened the wall's
  blind spot even if every other test passes.
- The public surface is lawful: every convenience (`willAdmit`,
  `provenance`, `sessionDigest`, `merge`, `close`, the fence rules)
  names the model law that licenses it. Do not add API the model does
  not license.
- The byte-identity claim holds only inside the corpus grammar: fixed
  ASCII keys, non-negative integers below 2^53, ASCII-identifier
  holders. Widening the value or holder domain is a ratification
  boundary, because JavaScript code-unit order and Lean code-point
  order diverge outside ASCII.
- Runtime dependency: `@foldlab/core` (the RFC 8785 seam) and nothing
  else. devDependencies for testing are permitted (fast-check, exact
  pin).
