# Freezing protocol

How a fixture becomes frozen, what freezing claims, and what it costs to
thaw one. One page, because a protocol nobody reads is a protocol nobody
follows.

This document exists because the repository whose epistemology is "the
fixture is evidence" had no statement of what freezing means. `AGENTS.md`
says `fixtures/stream-wall.json` is frozen and that regeneration needs "a
stated reason" — stated *where*, to *whom*, reviewed by *what*, was never
written down. Two of eight frozen fixtures have no regeneration path at all,
and the one pointer that does exist points at a file that does not exist.
The working parts of the protocol were already in the tree, spread across
`proto/go/cmd/wirefix/main.go`, ADR-0007, and `AGENTS.md`'s precepts; this
page assembles them.

## What a frozen fixture claims

A frozen fixture is a **recorded observation**, not a specification. It says:
on this date, this generator over this corpus produced exactly these bytes.
Everything downstream — a cross-language wall, a conformance suite, an
allowlist — is a claim that some *other* implementation reproduces that
observation.

Three consequences follow, and they are the whole reason for the ceremony:

1. **A digest mismatch is a finding, not a merge conflict.** `AGENTS.md`:
   "a digest mismatch means the change is wrong unless fixture regeneration
   was explicitly requested with a stated reason." The default disposition of
   a red wall is *investigate the code*, never *update the constant*.
   `go/cmd/streamfix` says the same in its own header: drift is "a finding to
   investigate, not a constant to update."
2. **A wall certifies only its corpus** (ADR-0007). The fixture's domain is
   part of the claim. A fixture without a stated corpus domain licenses
   readers to over-claim, which is the failure ADR-0007 exists to prevent.
3. **Both-sides-agree is not verification** (`AGENTS.md`). If the fixture was
   generated by one of the two implementations it walls, it proves the port
   reproduces the generator — not that either is right. Say which it is.
   `fixtures/jcs-rfc8785.json` is the model: its oracle is RFC 8785
   Appendix B, outside both implementations.

## Who freezes

The operator ratifies; an executor may run the generator. Freezing a NEW
fixture is a decision the spec must have fixed, or a `DECISIONS.md` entry the
task must carry — a fixture is a standing authority, and standing authorities
are not a builder's call. Re-freezing an EXISTING fixture is always an
operator decision, because it is the act of retiring evidence.

## What a freeze requires

At freeze time, in the same commit:

1. **A generator, named as a runnable command**, in the fixture's own
   `_provenance` field. Not "generated by the TypeScript fold implementation"
   — `cd go && go run ./cmd/streamfix > ../fixtures/stream-wall.json`. If the
   fixture cannot be regenerated by a command, it is not frozen; it is
   stranded, and a future disagreement has no way to distinguish drift from
   corruption.
2. **A corpus-domain statement** (ADR-0007's duty), in the fixture: what
   inputs it covers, and — said out loud — that nothing outside them is
   claimed.
3. **An oracle statement**: who says these bytes are right. If the answer is
   "the implementation that produced them", write that, and the fixture is a
   single-implementation PIN rather than a wall.
   `packages/core/fixtures/fold-pin.json` does this honestly and should be
   copied.
4. **Negative controls.** A fixture is a prover, and a prover that cannot
   fail proves nothing (`AGENTS.md`; `verify/AGENTS.md` states the model-gate
   form). Concretely: at least one test that mutates the fixture, or the
   input, and requires the wall to REFUSE — and, where a fixture pins several
   independent facts, one control per fact, each refuted on its own fact.
   Controls that keep the unrelated facts passing are what prove the facts
   independent.
5. **An overwrite guard in the generator.** `proto/go/cmd/wirefix/main.go`
   is the working precedent and the shape to copy:

   ```go
   if !force {
       if _, err := os.Stat(path); err == nil {
           return fmt.Errorf("%s exists; fixtures are frozen (use -force with a stated reason)", path)
       }
   }
   ```

   A generator that silently overwrites turns "regeneration requires a stated
   reason" into an honour system. `cmd/streamfix` writes to stdout and has no
   guard at all — the shell redirect is the overwrite, so the guard has to
   live in the ritual instead (below) until the generator grows one.

## The regeneration ritual

Thawing is four steps, in order. Skipping step 1 is the failure mode this
protocol exists to prevent.

1. **Establish that the mismatch is intended.** A red wall is evidence.
   Before any regeneration, the finding is reported with its minimized
   counterexample and STOPPED on (`AGENTS.md`, findings before fixes). The
   red test stays red until the operator ratifies a disposition. Regenerating
   first destroys the finding — permanently, because the old bytes were the
   only record of what the old behaviour was.
2. **Get the operator's ratification, with the reason in words.** The reason
   is a sentence about behaviour ("the transform pipeline now folds the
   rename before the filter, per D51"), never about the gate ("wall was
   red").
3. **Run the generator with `-force` (or the equivalent), and record the
   command verbatim in the commit message**, together with the stated reason
   and the sha of the fixture before and after. The commit message is the
   regeneration log; there is no separate ledger to fall out of date.
4. **Re-state the corpus domain and re-run the negative controls.** A
   regenerated fixture whose controls were not re-run is a fixture whose
   prover was never re-armed. If the domain changed, the claims that cite it
   in `VERIFICATION.md` change too, in the same commit.

Review: a regeneration diff is read by the operator, not rubber-stamped. The
diff of a frozen fixture is the diff of a claim.

**Two fixtures have no regeneration path.** `golden-conformance.json` has no
`_provenance` field, no generator anywhere in the tree, and four readers.
`fold-pin.json` names its producer in prose but no command. Both are read by
gates that would go red on drift, and neither offers any way to tell drift
from corruption. Restoring a generator for each is owed work, not a nicety:
until then, a disagreement on either fixture is unresolvable by construction.

## The two dangling pointers

Both cite `docs/primitives/MECH-attempts.md`. **That file and that directory
do not exist**, and no commit in this history created them.

- `fixtures/stream-wall.json:2` — `"Regeneration requires a stated reason in
  docs/primitives/MECH-attempts.md."`
- `go/cmd/streamfix/main.go:65-66` — the same sentence, in the generator that
  writes it.

**Proposed correction, not applied here** (the fixture is frozen; changing it
is itself a regeneration, and this lane reports rather than thaws):

> `"generated once by go/cmd/streamfix (go run ./cmd/streamfix); frozen. Regeneration requires a stated reason, per docs/FREEZING.md."`

The order matters. The sentence lives in `streamfix/main.go`, which WRITES
the fixture — so the correction is: edit the generator, then regenerate under
this protocol's own ritual, with the stated reason "the provenance pointer
named a document that never existed; repointing it at docs/FREEZING.md". Every
digest in the file must come back byte-identical except the `_provenance`
string; a single moved digest means the correction caught real drift and is a
finding, which is exactly what the ritual is for. That makes the pointer fix
the protocol's first exercise, and its first regression test.

## When a fixture should be deleted rather than re-frozen

`fixtures/wasm-wall-known-divergence.json` is the case to keep in view. It
freezes the exact extent of a KNOWN DEFECT (#27) so that a new one cannot
hide inside it. When the underlying fix lands — pinning `MapValueUpper` to
ASCII on both sides — the defect is gone, and an allowlist that outlives its
defect stops being a record and becomes a licence. Delete it with the fix.
Any fixture whose job is to describe something wrong inherits the same rule.
