## 3. The workflow as practiced

The loop that emerged, named so it can be repeated or amended:

1. **Spec first, grilled in batch.** The coordinator drafts with per-joint
   recommendations; the operator rules "all as recommended" or per-row. Ratification
   is a commit.
2. **Statement pins before dispatch.** Theorem statements are frozen as committed
   `Prop`s; seats deliver proofs only; a resistant statement is a STOP, never a
   reword.
3. **Scouts before rulings.** Before a design ruling, advisory agents take the model
   as it stands and collect receipts — expressibility probes, pinned-byte dossiers,
   end-to-end scenarios. Rulings are then made against evidence.
4. **Serialization points for carrier changes.** Constructor-arity changes (A-1, A-3,
   A-4) run exclusively, scheduled between seat waves; everything else is
   file-disjoint by the one-seat-one-new-module law.
5. **Adjudication at merge.** Full rebuild, gate, name-for-name axiom check on the
   merged state (not the branch state); merged trees are deleted immediately
   (operator policy, instituted this session).
6. **Everything lands as a commit the same day it is ruled** — the record and the
   repo never diverge overnight.

Roles: the operator rules and fires worktrees; the coordinator pins, briefs,
adjudicates, records; agents implement and investigate, trusted only through gates.

## 5. Failure modes observed, with the lesson each carries

1. **Spec-to-scaffold transcription gaps — twice in one day.** STORE-MODEL demanded
   `canonV` (§5) and duplicate-free fields (§5 clause 4); the scaffold implemented
   neither; both went unnoticed until a pin (Q11) and a scout probe (M1) hit them.
   *Lesson:* promotion of a formal artifact should include a clause-conformance
   table — every spec clause names its implementing definition or an explicit
   deferral. PROPOSED as standing checklist item.
2. **The no-push posture was policy without mechanism.** `origin/main` advanced to
   `f3f0988` and a codex branch reached the remote; cause not established
   (UNVERIFIED: which tool pushed; checked: reflog attribution is inconclusive from
   this session). *Lesson:* posture needs a mechanical guard — a pre-push hook in the
   main checkout and push-disabled remotes in agent worktrees. PROPOSED.
3. **Ratified aspiration outran the model.** KICKOFF §16/§17 convergence claims
   (provenance merge, naming convergence) were written before anyone checked them
   against array order-sensitivity; scout C demoted both. *Lesson:* aspirational
   claims in ratified docs carry an explicit unchecked-against-the-model marker until
   probed, or the scout wave runs before the thrust doc. PROPOSED.
4. **Same-day statement amendment (benign, by luck of sequencing).** The M15 entity
   pin was amended hours after freezing (Q11). Zero cost only because no proof
   existed yet. *Lesson:* pin early precisely because elaboration flushes gaps, but
   hold dispatch until adjacent design questions on the same statement are ruled.
5. **Editing shared modules while seats were in flight was safe by analysis, not by
   rule.** The Q11/M1 edits were argued additive-safe (constructor arity stable,
   no seat-referenced names changed) and the merge proved it — but the safety
   argument lived in the coordinator's head. *Lesson:* write the rule down; it now
   is: **additive definitions are safe during dispatch; arity or name changes to
   anything a seat imports are serialization points.**

## 6. Standing amendments — RATIFIED (operator, 2026-08-25, all five)

1. Clause-conformance table required at formal-artifact promotion (§5.1).
2. Mechanical push guard (§5.2): a `pre-push` hook in the repo's common git dir
   refuses every push unless `FOLDLAB_ALLOW_PUSH=1` is set for that invocation.
   Because hooks live in the common dir, the guard covers every worktree of this
   repo — coordinator, codex, and agent trees alike. Hooks are untracked by git;
   this entry is the record, and the hook must be re-installed on any fresh clone
   (added to the dual-host checklist).
3. Unchecked-claim markers in ratified prose (§5.3): an aspiration not yet probed
   against the model carries an explicit marker until a probe lands.
4. The additive-vs-arity rule (§5.5) is law: additive definitions are safe during
   dispatch; arity or name changes to anything a seat imports are serialization
   points.
5. The audit series continues: one entry per major session, this register.
