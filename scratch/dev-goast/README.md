# The Go AST artifacts — sizing a Lean Go-printer

Measured 2026-08-18 at `7d19ab7` (origin/main, the commit that merged
DEV-822) on go1.26.5 darwin/arm64,
with the Go toolchain's own packages: `go/parser`, `go/ast`, `go/token`,
`go/printer`, `go/format`, `text/tabwriter`. Nothing here is hand-counted.

Reproduce everything: `scratch/dev-goast/measure.sh` from the repository root.
It writes only into `scratch/dev-goast/artifacts/`, and it runs the generator
against a temporary root so a mutated corpus can never reach the tree.

## The finding, first

The Go side has exactly ONE corpus-generated file:

    go/kmconform/tables_generated.go   694 lines, 29,896 bytes
    sha256 5d19cc38470a130a041261f8c9361d438298aad45177034550b63dc271d30426

Generated by `cd go && go run ./cmd/kmgen` from
`packages/plait/fixtures/kernel-conformance.ndjson` — the same corpus the
TypeScript generators read. Its regeneration gate is
`go/cmd/kmgen/regeneration_test.go` and it runs in CI at
`.github/workflows/gates.yml` (`go — go test ./...`, `-count=1`,
`working-directory: go`).

Two other files carry a `DO NOT EDIT` banner and are NOT targets:
`scratch/km-polyglot/kmconform/kmconform_exemplar.go` and
`scratch/km-polyglot/kmgen.go` are a retired scratch spike that nothing
imports. `proto/go/` has no generated file at all.

The second half of the finding is about the generator, not the file.
`cmd/kmgen` is a `strings.Builder` — 719 lines of `fmt.Fprintf` and
`out.WriteString(\`...\`)` over raw Go source text, finished with one
`format.Source` pass (`main.go:108`). There is no typed target grammar on
the Go side at all. That is the same defect DEV-812 names on the TypeScript
side, and the Go side is at the same stage: the bytes are correct, the
grammar is a string.

## The layout facts — the part that decides the difficulty

    format.Source(src) == src                                          true
    printer.Config{Mode: UseSpaces|TabIndent, Tabwidth: 8} == src      true
    gofmt -l over the whole go/ module                                 prints nothing
    lines with trailing whitespace / CRLF                              0 / 0
    lines indented with a tab                                          358
    lines carrying an interior tab                                     0
    lines carrying elastic column alignment (>=2 spaces)               125
    lines printer.RawFormat (no tabwriter) spells differently          155
    RawFormat + tabwriter(0, 8, 1, ' ', DiscardEmptyColumns|TabIndent) byte-identical
    blank lines / max consecutive                                      70 / 1
    longest line                                                       722 bytes
    non-ASCII bytes                                                    12

Read that as three claims.

**One.** The file is a gofmt fixed point, so the layout question is not
"what layout do we want" — it is "reproduce gofmt over this census", which
is a strictly smaller problem than gofmt.

**Two.** The layout algorithm is fully named and small. `go/printer` in
`RawFormat` mode emits the node layout with `\t` cell separators; piping
that through `text/tabwriter` with go/printer's own five parameters —
minwidth 0, tabwidth 8, padding 1, padchar `' '`, mode
`DiscardEmptyColumns|TabIndent` — reproduces the committed bytes exactly.
Measured, not cited.

**Three.** The elastic-alignment pass is load-bearing on 155 of 694 lines,
so a printer that skips it is wrong on 22% of the file. The mutation arm
shows it moving: widening one corpus kind name from `schema` to `schemas`
repads the column in a const block AND in a one-line function body —

    -	KindSchema     DeclKind = 0
    +	KindSchemas    DeclKind = 0
    -func NewSchemaDigest(id uint64) SchemaDigest         { return SchemaDigest(id) }
    +func NewSchemasDigest(id uint64) SchemasDigest       { return SchemasDigest(id) }

## Comments and the header convention

58 comment groups, 153 comment lines, all `//` — zero `/* */`. 52 groups
are `Doc` (attached to a declaration), 6 float. Zero comment groups appear
inside a function body, which removes the hardest comment-placement case
from the printer entirely. Eleven header lines precede the first blank.

The banner matches Go's own convention exactly
(`^// Code generated .* DO NOT EDIT\.$`):

    // Code generated by cmd/kmgen from ../../packages/plait/fixtures/kernel-conformance.ndjson. DO NOT EDIT.

One directive is emitted: `//foldlab:brand`, twelve times, one per kind,
read by `go/brandlint`. It is a comment to `go/ast` and a declaration to
the estate, so a printer that drops comments drops a lint's input.

The 12 non-ASCII bytes are four U+2014 em dashes, all in prose comments
`cmd/kmgen` holds as its own Go string literals (`tables_generated.go`
lines 476, 523, 652, 653) — none come from the corpus. This collides with
`verify/projections` ruling P5, whose `asciiDoc` transliterates U+2014 to
`--` and refuses anything it cannot name. Byte parity with the committed
Go file requires the raw em dash. That is a real conflict and it needs a
ruling, not a preference.

## Corpus reach

    generated-file lines                                     695
    lines carrying a verbatim corpus scalar                   403
    further lines carrying a kmgen-minted identifier           36
    corpus-reached lines                                      439 (63.2%)
    generator template text alone                             256 (36.8%)

63% of the emission is corpus data, and the groups it needs — refusal
rows with their law, repair and applicability; encoding vectors; admission
vectors; program vectors — are exactly the ones the generic environment
walk deliberately does not carry (`verify/projections/DECISIONS.md` P3,
"Leave refusal values to model-specific producers"). At `7d19ab7` the
toolkit's Lean topology gate still requires exactly kernel by path
(`run.sh:98`), while DEV-822 gave the GATE SCRIPT a read of the corpus for
the manifest wall (`run.sh:35`, `run.sh:216`) — a bash read, not a package
dependency.

The A3 sitting record on DEV-772 (2026-08-19T00:14) rules the shape for
the TypeScript target: the printer lives in `verify/unity` beside
`EmitMain`, which already owns the corpus data; the AST stays in
`verify/projections`; each package keeps its one lawful reach. The
measurement above says a Go printer stands in the same position for the
same reason. Whether the ruling extends to a third target, or was scoped
to the TypeScript printer it was cut for, is the grill's to say — not this
artifact's.

## The parity wall already in the tree

`go/cmd/kmgen/regeneration_test.go` runs four checks, and they are the
shape any Lean-side wall should copy rather than reinvent:
`TestGeneratedTablesAreAFreshEmission` (committed versus fresh),
`TestTheEmissionIsGofmtCanonical`, `TestTheGeneratorIsDeterministic` (two
runs), `TestTheGeneratorRefusesAMalformedCorpus` (the control mutation —
`"format":2` becomes `"format":9`). Executed here at head:

    committed  5d19cc38470a130a041261f8c9361d438298aad45177034550b63dc271d30426
    fresh run1 5d19cc38470a130a041261f8c9361d438298aad45177034550b63dc271d30426
    fresh run2 5d19cc38470a130a041261f8c9361d438298aad45177034550b63dc271d30426

Three mutation arms, run against a temporary root:

| mutation | result |
| --- | --- |
| one character inside one docstring | 2 lines of Go move |
| one kind name widened (`schema` → `schemas`) | 12 lines move, including two elastic columns |
| one kind renamed with a live cross-reference (`lane` → `vein`) | the generator REFUSES through the corpus validator |

The third is the important one: `kmgen` is not more tolerant than the
consumer it generates for. `generate()` calls `kmconform.CheckBothWays`
before it writes a byte.
