And `def List.dlookup (a : α) : List (Sigma β) → Option (β a) | [] => none | ⟨a', b⟩ :: l => if h : a' = a then some (Eq.recOn h b) else dlookup a l` (L155) is **our `Word.find`**, first-binding resolution and all. `Option.or` (`lean4 src/Init/Data/Option/Basic.lean#L253`) is `| some a, _ => some a | none, b => b` — pointwise identical to our `(toStore w₁ a).elim (toStore w₂ a) some`. Docs: `DOCS/Mathlib/Data/List/Sigma.html#List.dlookup_append`.

**B. Left-biased union is a named Mathlib construction with our two lemmas.**
`AList.union` — docstring: *"It is left-biased: if there exists an `a ∈ s₁`, `lookup a (s₁ ∪ s₂) = lookup a s₁`."* (`SRC/Mathlib/Data/List/AList.lean#L385`). `AList.lookup_union_left {a} {s₁ s₂} : a ∈ s₁ → lookup a (s₁ ∪ s₂) = lookup a s₁` (L415) and `AList.lookup_union_right : a ∉ s₁ → lookup a (s₁ ∪ s₂) = lookup a s₂` (L419) are our `find_append_of_some` / `find_append_of_none`. Underlying: `List.dlookup_kunion_left/right` (`Sigma.lean#L723,L738`). **Caveat that keeps this from being an exact match:** `AList` carries a `NodupKeys` invariant, so `AList.union` *erases* shadowed keys (`kunion` is defined with `kerase`), whereas our `Word` keeps shadowed bindings physically present and lets `find` make them inert. Our `toStore_append_shadowed` has no `AList` counterpart — it is a statement about a representation Mathlib's `AList` forbids. `Mathlib/Data/Finmap.lean` is the quotiented version; `Mathlib/Data/Finsupp/AList.lean` bridges `AList.lookupFinsupp` / `Finsupp.toAList`.

**C. `FreeAddMonoid.countP` is `View.height ∘ columnBy`, already bundled.**
`def FreeAddMonoid.countP (p : α → Prop) [DecidablePred p] : FreeAddMonoid α →+ ℕ` with `countP_apply : l.countP p = l.toList.countP p` — `SRC/Mathlib/Algebra/FreeMonoid/Count.lean#L70,L75`. The file's own header says it is *"`List.count` as a bundled homomorphism."* That is exactly our composite "filter by a pointwise classifier, take the length" — bundled as an `AddMonoidHom`, which is what `View.height` reconstructs by hand. `FreeMonoid.count [DecidableEq α] (x : α) : FreeMonoid α →* Multiplicative ℕ` is the multiplicative twin. Docs: `DOCS/Mathlib/Algebra/FreeMonoid/Count.html`.

**D. `MonoidHom.prod` is `View.prod`.**
`protected def MonoidHom.prod (f : M →* N) (g : M →* P) : M →* N × P where toFun := Function.prod f g; map_one' := Prod.ext f.map_one g.map_one; map_mul' x y := Prod.ext (f.map_mul x y) (g.map_mul x y)` — `SRC/Mathlib/Algebra/Group/Prod.lean#L392`, with `MonoidHom.prod_apply : f.prod g x = (f x, g x)` (L407). Byte-for-byte the shape of our `View.prod`. Docs: `DOCS/Mathlib/Algebra/Group/Prod.html#MonoidHom.prod`.

**E. `FreeMonoid.map` — the hom version of `List.map`, which we don't have.**
`def FreeMonoid.map (f : α → β) : FreeMonoid α →* FreeMonoid β where toFun l := ofList <| l.toList.map f; map_one' := rfl; map_mul' _ _ := List.map_append` (`SRC/…/FreeMonoid/Basic.lean#L382`), with `map_of`, `map_comp`, `map_id`, and `lift_of_comp_eq_map : (lift fun x ↦ of (f x)) = map f` (L407). Notably Mathlib bundles **`map`** but not **`filter`** as a `FreeMonoid` hom — so our `View.column` (filter-as-hom) has no Mathlib twin, only its underlying `List.filter_append`.

**F. `FreeMonoid.mkMulAction` — the word acting on a state, which is what an interpreter is.**
`def mkMulAction (f : α → β → β) : MulAction (FreeMonoid α) β where smul l b := l.toList.foldr f b; one_smul _ := rfl; mul_smul _ _ _ := List.foldr_append` (`SRC/…/Basic.lean#L354`). This is the free-monoid-action packaging of "replay a word against a state" — directly adjacent to threading admission through the interpreter, and we have no such abstraction.

**G. `MonoidHom.mrange` and `Submonoid.closure` — the image/generated pair.**
`def MonoidHom.mrange (f : F) : Submonoid N := ((⊤ : Submonoid M).map f).copy (Set.range f) Set.image_univ.symm` with `coe_mrange : (mrange f : Set N) = Set.range f := rfl` and `mem_mrange : y ∈ mrange f ↔ ∃ x, f x = y := Iff.rfl` — `SRC/Mathlib/Algebra/Group/Submonoid/Operations.lean#L649,L653,L657`. `def Submonoid.closure (s : Set M) : Submonoid M := sInf { S \| s ⊆ S }` with `closure_le : closure s ≤ S ↔ s ⊆ S` (the Galois connection) and `closure_induction` — `SRC/Mathlib/Algebra/Group/Submonoid/Basic.lean#L113,L139,L162`. "The set of stores reachable by admission" is `mrange` of the projection; "the sub-store generated by a seed set" is `closure`.

**H. Quotient factorization in full generality: `Con`.**
`structure Con [Mul M] extends Setoid M where mul' : ∀ {w x y z}, r w x → r y z → r (w * y) (x * z)` (`SRC/Mathlib/GroupTheory/Congruence/Defs.lean#L69`); `Con.ker (f : F) : Con M := { toSetoid := Setoid.ker f, … }` (`Congruence/Hom.lean#L52`); `def Con.lift (H : c ≤ ker f) : c.Quotient →* P` (`Congruence/Hom.lean#L189`); first isomorphism theorem `noncomputable def Con.quotientKerEquivRange (f : M →* P) : (ker f).Quotient ≃* MonoidHom.mrange f` (`Congruence/Basic.lean#L190`). This is the general form of the target-3 claim: any query is exactly determined by its kernel congruence, and admission-order-insensitivity is the statement that `Perm` refines that kernel.

**I. `Filter` — the LIMIT-STABLE rung. This row is exact.**
- `protected def Filter.Eventually (p : α → Prop) (f : Filter α) : Prop := { x \| p x } ∈ f`, notation `∀ᶠ x in f, p x` — `SRC/Mathlib/Order/Filter/Defs.lean#L281,L285`. Docs: `DOCS/Mathlib/Order/Filter/Defs.html#Filter.Eventually`.

- Combinators, all in `Mathlib/Order/Filter/Basic.lean`: `Filter.eventually_iff : (∀ᶠ x in f, P x) ↔ { x \| P x } ∈ f` (L630); `Filter.Eventually.of_forall (hp : ∀ x, p x) : ∀ᶠ x in f, p x` (L655); `Filter.Eventually.mp (hp) (hq : ∀ᶠ x in f, p x → q x) : ∀ᶠ x in f, q x` (L674); `Filter.Eventually.mono (hp) (hq : ∀ x, p x → q x) : ∀ᶠ x in f, q x` (L679); `protected Filter.Eventually.and : f.Eventually p → f.Eventually q → ∀ᶠ x in f, p x ∧ q x` (L649); `Filter.eventually_and : (∀ᶠ x in f, p x ∧ q x) ↔ (∀ᶠ x in f, p x) ∧ ∀ᶠ x in f, q x` (L688). Also `Filter.frequently_atTop : (∃ᶠ x in atTop, p x) ↔ ∀ a, ∃ b, a ≤ b ∧ p b` (`AtTopBot/Basic.lean#L82`) and `Filter.Eventually.exists_forall_of_atTop` (alias, L86).
- Notes for the judge lattice: `Eventually` is closed under **finite** conjunction (`eventually_and`) and implication, and is **monotone in the filter** — it is a filter of propositions, not a lattice rung with joins. `atTop` on our admission index (`ℕ` word length) is the intended instance; `IsDirectedOrder` is the required hypothesis, and `ℕ` satisfies it.

**J. `Finsupp.liftAddHom` — a second universal property we don't exploit.**

Group-by queries out of a `Finsupp` are determined by their action on single columns, the same way word queries are determined by their action on single bindings.

## Five-line summary

1. **Standard-issue.** Our word monoid, the `View` homomorphism laws, the Perm-quotient factorization, and every list lemma we cite (`filter_append`, `length_append`, `foldr_append`, `append_assoc`) are textbook Mathlib/Lean-core objects; `FreeMonoid.lift` is a genuine `Equiv (α → M) ≃ (FreeMonoid α →* M)` and `FreeMonoid α` is *definitionally* `List α`, so the fit is literal, not analogical.
2. **Standard-issue and already bundled better than ours.** `FreeAddMonoid.countP : FreeAddMonoid α →+ ℕ` is our `View.height ∘ columnBy`; `MonoidHom.prod` is our `View.prod`; `SupBotHom` is `View`'s exact structural twin; `List.dlookup_append` is `Word.toStore_append`; `AList.lookup_union_left/right` are our two `find_append` lemmas, under a docstring that says "left-biased" in so many words.
3. **House-shaped where we are weaker.** `View` carries `merge`/`empty` with **no** monoid laws on the carrier and no order — deliberately, per the module's own comment — so it is strictly below `MonoidHom` and `SupBotHom`; and our join laws (`toStore_append_comm`, `toStore_append_self`) are *conditional* on `Store.Compatible`, whereas `SemilatticeSup` gets `sup_comm`/`sup_idem` unconditionally from the order.
4. **House-shaped where we are stronger.** `wf`/`resolvesIn` are decidable `Bool` scans over a word that permits shadowing; Mathlib has **no** `Decidable` instance for any reachability closure, **no** DAG/acyclicity/topological-sort API on `Digraph` or `Quiver`, and its only topological-order content is the non-constructive Szpilrajn theorem `extend_partialOrder` proved by Zorn. Admission well-formedness is genuinely ours.
5. **The one rung with an exact Mathlib name we should be using its vocabulary for** is LIMIT-STABLE: `Filter.eventually_atTop : (∀ᶠ x in atTop, p x) ↔ ∃ a, ∀ b, a ≤ b → p b`, with `Eventually.mono`, `Eventually.and`, `Eventually.of_forall`, `eventually_and`, and the dual `frequently_atTop`; note it is a *filter* of propositions — finite conjunctions and monotone implication only, no joins.
